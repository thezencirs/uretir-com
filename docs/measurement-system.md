# Measurement System

## Purpose

Uretir measures whether the product creates durable user value. Measurement exists to improve discovery, knowledge depth, return behavior, community participation, and AI usefulness—not to inflate vanity metrics.

The repository currently provides a provider-neutral event contract. It does not send telemetry, set analytics cookies, persist interaction events, or claim a production baseline. Search Console, real-user performance monitoring, and a consent-aware analytics provider remain operational integrations that must be approved separately.

## North-star outcomes

Product reviews should evaluate the following outcomes together:

| Outcome | Primary evidence | Guardrail |
| --- | --- | --- |
| Qualified organic discovery | Search Console clicks and landing-page queries | Do not optimize impressions without usefulness |
| Knowledge depth | Internal discovery selections and meaningful next-page views | Exclude accidental reloads and bot traffic |
| Return behavior | Consent-aware returning-reader cohorts | Do not create identity fingerprints |
| Authority | Approved entity coverage, source quality, citation freshness, earned references | Page count is not authority |
| AI usefulness | Completed decision paths, source openings, and related-guide discovery | Do not record prompt text by default |
| Community value | Saved knowledge, trusted contributions, and healthy return participation | Registrations alone are not success |

No score in this document is a current production result. Baselines begin only after the measurement owner verifies the production property, consent behavior, bot filtering, and data quality.

## Event contract

Interactive elements opt in with three attributes generated by `analyticsAttributes()`:

- `data-analytics-event`: a version-controlled event name.
- `data-analytics-surface`: the product surface that owns the interaction.
- `data-analytics-target`: an optional short machine identifier.

`AnalyticsEventBridge` converts an opted-in click, form submission, or allowlisted control change into the local `uretir:analytics` browser event. The bridge reads no form or control value and performs no network or storage operation. A future adapter may subscribe to this channel only after privacy, consent, retention, ownership, and failure behavior are documented.

Current events:

| Event | Meaning | Current surfaces |
| --- | --- | --- |
| `navigation_select` | A primary navigation destination was selected | Header |
| `search_submit` | A content or scenario search was submitted | Homepage, blog, PuanAI |
| `filter_select` | A discovery filter was selected | Blog, PuanAI |
| `discovery_select` | A related content or product path was selected | Content discovery, PuanAI |
| `ai_intent_select` | A predefined shopping intent was selected | PuanAI |
| `ai_priority_select` | A recommendation priority was selected | PuanAI |
| `ai_prompt_submit` | The local intent classifier was invoked | PuanAI |
| `ai_recommendation_open` | A disclosed sample recommendation was opened | PuanAI |
| `ai_reset` | The advisor flow was restarted | PuanAI |
| `contact_select` | A transparent contact channel was selected | Contact, footer |
| `rss_select` | The RSS channel was selected | Newsletter, footer |
| `theme_select` | The color theme was changed | Global theme control |

## Privacy and data minimization

The event contract forbids:

- Search queries and AI prompt text.
- Email addresses, card details, account IDs, names, or free-form input.
- Full URLs containing query strings or fragments.
- Fingerprinting, cross-site identifiers, or hidden profile enrichment.
- Provider SDKs loaded before the approved consent rule permits them.

Targets are restricted in code to short lowercase machine identifiers. Product code must not bypass the helper with ad hoc data attributes. A future provider adapter must maintain an explicit allowlist and reject unknown fields at runtime.

## Funnel definitions

Definitions are stable before numbers are collected:

1. **Organic discovery:** verified search click to an indexable canonical page.
2. **Knowledge continuation:** a `discovery_select` followed by a successful internal route view.
3. **PuanAI decision path:** intent or local prompt, priority selection, then recommendation open.
4. **Trust follow-through:** opening a source, methodology, or provenance surface after an AI result.
5. **Return cohort:** a privacy-approved returning browser or signed-in member revisiting within the declared window.

Funnel steps must remain comparable across releases. If a definition changes, version the metric and annotate the change date; never splice incompatible definitions into one trend line.

## Provider integration gate

Before connecting a production analytics provider:

1. Name the Product, Data, Privacy, and Engineering owners.
2. Document lawful purpose, consent behavior, retention, deletion, and data residency.
3. Define bot filtering, internal-traffic exclusion, and release identifiers.
4. Map only the allowlisted event contract; do not enable automatic form or text capture.
5. Test consent denied, consent withdrawn, blocked script, offline, and provider outage states.
6. Verify that the public experience and Core Web Vitals do not regress.
7. Publish a privacy-policy update before collection begins.
8. Validate dashboards against raw event samples and record the baseline date.

## Operating cadence

- Weekly: inspect collection health, broken funnels, crawl errors, and anomalous event volume.
- Monthly: review organic discovery, internal discovery quality, return behavior, authority coverage, and AI usefulness together.
- Quarterly: retire unused events, audit consent and retention, and challenge whether each metric still represents user value.

Analytics is evidence for judgment, not a substitute for editorial review, user research, or source quality.
